# معماری ماژول ربات Nexora

## معماری چند-مستاجری (Multi-Tenant) — توضیح کامل

### تک‌مستاجری یعنی چه؟

هر نصب، فقط یک کسب‌وکار را سرویس می‌دهد:

```
سرور علی → یک ربات → مشتریان علی
سرور ماکان → یک ربات دیگر → مشتریان ماکان   ← نصب کاملاً جدا
```

اگر ماکان بخواهد ربات داشته باشد، باید سرور بخرد، پنل نصب کند، و شما هم باید جدا پشتیبانی کنید.

### چند-مستاجری یعنی چه؟

**یک نصب، چند کسب‌وکار مستقل** که داده‌هایشان کاملاً از هم جداست:

```
                 سرور علی (یک نصب)
                        │
        ┌───────────────┼───────────────┐
        │               │               │
   ربات Nexora     ربات ماکان      ربات رضا
   (مستاجر ۱)      (مستاجر ۲)      (مستاجر ۳)
        │               │               │
   مشتریان علی    مشتریان ماکان   مشتریان رضا
```

هر مستاجر:
- **توکن ربات خودش** را دارد (از BotFather می‌گیرد)
- کاربران، پلن‌ها، سفارش‌ها و کیف پول **کاملاً جدا**
- برند، قیمت، و شماره کارت خودش
- **هرگز داده‌ی مستاجر دیگر را نمی‌بیند**

ولی همه روی **یک سرور، یک کد، یک به‌روزرسانی** اجرا می‌شوند.

### چرا برای شما حیاتی است؟

**سناریوی واقعی:** ماکان واسطه‌ی شماست. با چند-مستاجری:

1. ماکان از BotFather یک ربات می‌سازد: `@MacanVPNBot`
2. توکن را در پنل شما وارد می‌کند
3. ربات ماکان **بلافاصله فعال می‌شود** — با برند خودش، قیمت‌های خودش
4. ماکان از شما اعتبار عمده می‌خرد (مثلاً ۵۰۰ هزار تومان با ۲۵٪ تخفیف)
5. هر فروش ماکان، از اعتبارش کم می‌شود
6. مشتریان ماکان اصلاً نمی‌دانند Nexora وجود دارد

**نتیجه برای شما:** به‌جای فروش به ۱۰۰۰ مشتری، به ۲۰ واسطه می‌فروشید که هرکدام ۱۰۰ مشتری دارند. کار پشتیبانی‌تان کم می‌شود، درآمدتان بیشتر.

**نتیجه برای خریدار پنل:** او هم می‌تواند همین کار را بکند. این تنها قابلیتی است که مستقیم درآمدش را چند برابر می‌کند — و دلیل خرید لایسنس Pro.

### چطور پیاده می‌شود؟

هر جدول دیتابیس یک ستون `tenant_id` دارد. هر کوئری خودکار با آن فیلتر می‌شود:

```sql
-- هرگز بدون tenant_id کوئری نمی‌زنیم
SELECT * FROM users WHERE tenant_id = ? AND telegram_id = ?
```

یک لایه‌ی محافظ در کد این را **اجباری** می‌کند تا اشتباه انسانی باعث نشت داده بین مستاجرها نشود.

### سلسله‌مراتب

```
مستاجر اصلی (شما)
    ├── واسطه ۱ (مستاجر فرزند)
    │     └── اعتبار: ۵۰۰,۰۰۰ تومان
    ├── واسطه ۲
    └── واسطه ۳
```

واسطه‌ها `parent_tenant_id` دارند. شما آمار همه را می‌بینید، آن‌ها فقط خودشان را.

## جداسازی از پنل ساب — تضمین عدم خرابی

**نگرانی شما درست است.** پنل ساب الان کار می‌کند و نباید خراب شود. به همین دلیل:

| | پنل ساب | ماژول ربات |
|---|---|---|
| سرویس | `nexora-panel` (پورت 8100) | `nexora-bot` (پورت 8200) |
| دیتابیس | `data/config.json` | `data/bot.db` (SQLite) |
| کد | `backend/app.py` | `bot/` (کاملاً جدا) |
| وابستگی | fastapi, uvicorn | + requests |

**اگر ربات کرش کند، پنل ساب و صفحه‌ی مشتریان دست‌نخورده کار می‌کنند.** برعکسش هم همین‌طور.

پنل مدیریت فقط از طریق HTTP با ماژول ربات حرف می‌زند — مثل دو برنامه‌ی مستقل.

## سیستم سکه

بر اساس ایده‌ی شما، با پله‌های قابل تنظیم:

| سکه | تخفیف |
|---|---|
| ۲۰ | ۱۰٪ |
| ۴۰ | ۲۰٪ |
| ۶۰ | ۳۰٪ |
| ۸۰ | ۴۰٪ |
| ۱۰۰ | ۵۰٪ |

**قوانین:**
- سکه فقط با **خرید موفق** زیرمجموعه داده می‌شود (نه صرف عضویت) — جلوی سوءاستفاده را می‌گیرد
- کاربر می‌تواند سکه نگه دارد تا به پله‌ی بالاتر برسد
- هنگام استفاده، سکه‌ها مصرف می‌شوند
- سقف تخفیف قابل تنظیم (پیش‌فرض ۵۰٪)
- همه‌ی پله‌ها از پنل قابل ویرایش‌اند

## پرداخت — فقط کارت‌به‌کارت

طبق نظر شما، درگاه‌های آنلاین حذف شدند.

**جریان کار:**

```
۱. مشتری پلن را انتخاب می‌کند
۲. ربات: مبلغ + شماره کارت + نام صاحب حساب
۳. مشتری رسید (عکس یا متن) می‌فرستد
۴. ربات فوراً در گروه مدیریت اعلان می‌دهد
۵. شما در پنل یا همان گروه: تایید / رد
۶. با تایید: کانفیگ خودکار ساخته و ارسال می‌شود
```

**نکات مهم:**
- شماره کارت‌های متعدد با چرخش خودکار (برای پخش تراکنش)
- مهلت پرداخت (پیش‌فرض ۳۰ دقیقه) و بعد لغو خودکار
- تشخیص رسید تکراری
- تاریخچه‌ی کامل هر سفارش

## گروه مدیریت با تاپیک

ربات یک گروه خصوصی می‌سازد (یا شما می‌سازید و ربات را ادمین می‌کنید) و تاپیک‌ها را خودکار ایجاد می‌کند:

| تاپیک | محتوا |
|---|---|
| 🧾 رسیدها | هر رسید جدید با دکمه تایید/رد |
| 👥 کاربران | ثبت‌نام جدید، تغییر وضعیت |
| 📊 آمار روزانه | گزارش خودکار ساعت ۲۳:۵۹ |
| 💾 بک‌آپ | فایل بک‌آپ خودکار روزانه |
| 🎫 تیکت‌ها | پیام‌های پشتیبانی |
| ⚠️ هشدارها | خطای سرور، اتمام اعتبار واسطه |
| 🔁 تمدیدها | تمدید خودکار و دستی |

**مزیت:** بدون باز کردن پنل، از داخل تلگرام همه‌چیز را می‌بینید و تایید می‌کنید.
